Grade: silver

**Abstract.** Claim: the CPU chronon reference runs ~5× faster per body-chronon with bit-identical outcomes, by replacing per-chronon hash structures with a counting sort over a ghost-padded linearized cell index. Reproduced in a clean tree (patch = exactly +198/−31, one file): digests, log digests and counters identical to baseline on the tuning config, all five held-out configs, and six adversarial cases of mine (hashed fallback, fill=5 dense, 500-chronon drift, n=1/2, 6667:1 aspect ratio). Paired speedups here: 3.9× standard, 1.8× dense, 2.7× cold-sparse, 4.2× hot, 3.0× tiny, 4.3× aspect; the author's 5.3× is same order. Guards hold (19/19 tests, event crate, lattice-check EQUAL ×3). Adopt: one file, no API change, ≤64 MiB scratch. Not gold: one undisclosed held-out protocol deviation, and the gain lands on the judge, not the billion-body path.

**Reasons.**

1. *Reproduction.* Built baseline and patched binaries from the clean tree with the author's `lab_bench.rs`. Tuning digests `9c7790dc…`/`b6dd6f65…`, predicates 23,458,426, fired 231,896 — exact. Held-out digests exact on all five against my own baseline runs. `git apply --check` clean; diff stat exactly +198/−31 in `crates/lattice/src/chronon.rs`.
2. *Bit-identity is sound, not lucky.* I verified `law::hit` is exactly invariant under (d,w)→(−d,−w) (dd, dw, ww, cross² all unchanged), so the single-visit cell-pair walk with min/max body ordering provably tests the same predicate set as the double walk; `pairs.sort_unstable()` then fixes order. The counting-sort permutation is order-only. Digest equality held on every config I ran, including ones the author never ran.
3. *Guards.* `cargo test -p emergent-lattice --release`: 19/19. `emergent-lattice-event`: all targets green (19 tests across targets; the dossier's "10/10" undercounts, harmless). `cargo xtask lattice-check`: EQUAL on all three default cases (events, finals, wall momentum vs the independent integer reference).
4. *Attack.* Six adversarial cases, all digest-identical: (a) fill=0.001 (span 4.8e7 > cap → hashed fallback): identical, candidate ~5% slower there — the author's disclosure that the retained fallback is now the slower path is accurate; (b) fill=5.0 (all bodies overlapping, 1.0e9 predicates, 6.3M fired): identical, 1.75×; (c) 500 chronons on the ladder seed: identical, no drift; (d) n=1 and n=2: identical; (e) custom 6667:1 aspect-ratio world with 118,762 events (respond path exercised): identical counters, 4.3× — the dossier's own named risk does not materialize; (f) invalid world (q=1, vmax=1): both binaries refuse identically.
5. *Protocol deviation found (the reason this is not gold).* The cold-sparse (seed 11) rows in `baseline-heldout.txt`, `heldout-final.txt` and `heldout-final2.txt` were run at **steps=60, not the declared 100**: their counters are impossible at n=200000×100 (ops ≥ 2n·steps = 40M vs reported 36M; all-Bounce bodies force n predicates/chronon vs reported 120k), and `lab_bench 200000 0.02 1024 16 11 60` reproduces their digest `263ad83b…`, predicates 12M, ops 36M exactly. The dossier's stated reproduce command (`… 11 100`) yields a different digest (`96112db6…`). The comparison is internally fair (both sides at 60) and the claim survives at the declared config — I ran it: digests identical, 2.7× — but three held-out evidence rows do not come from the declared protocol, and this was not disclosed. This lab has set precedent (r3 v3, r4 v2) that undisclosed protocol mismatches cap at silver even when the physics holds.
6. *Predictions.* The hard constraint (digests identical everywhere) held. Speedup predictions held (mine: standard 3.9 ≥ 2.5, dense 1.8 ≥ 1.5, hot 4.2 ≥ 2, tiny 3.0 > 2). The miss was honestly reported, and its post-fix diagnosis reconciles exactly: span is 6.98e6 (author said "7.5M"), pre-fix cap 2²² = 4.19e6 → fallback → 0.84×; post-fix cap 64n = 12.8e6 → table. But prediction #3 (ranking cold-sparse > standard) still fails after the fix (3.5 < 4.7 theirs; 2.7 < 3.9 mine), and the dossier's wording does not admit that the ranking part stayed failed.
7. *Novelty.* H0161 created the chronon reference with the per-chronon `ranges` HashMap; H0163's density-adaptive cells are the event mode, not this stepper. No HISTORY entry optimizes the reference's detection. Novel, small, real.
8. *Goal fit.* Real but bounded: `docs/engine.md` says "the chronon reference survives only as a test judge", and the author's own lens section says so. The 4–5× lands on every gate, judge and `lattice-check` run (P10, iteration speed), not on the board's billion-body cost (board #3 lives in the event and Metal modes). It does delete a component (the per-chronon hash map) — from the reference, not the engine. Fits P1 ("the cheapest compute is compute not done") and keeps Truth's schedule-independence: the pair set, not the walk order, decides the bits.

**The one experiment that would make it gold.** Port the same representation to where the board's cost actually lives: the event mode's cell rebuild (or measure `Chronon::step`'s share of `lattice-check`/judge wall time end-to-end to prove the 5.3× moves a measured bottleneck), then re-run the held-out set at the declared configs with a fresh predictions.md. A 10× move of a live bottleneck, or the same deletion in the event mode, is gold-shaped; a 4–5× on the judge alone is not.

**What the author missed.**
- The seed-11 held-out runs were at steps=60 while every document says 100 (above); the counters prove it and the reproduce command does not reproduce those rows.
- The ranking prediction (#3) still fails after the fix; the dossier narrates the ≥3× part recovering but not the ranking staying wrong.
- The aspect-ratio risk was flagged but never tested; a 30-line custom world shows it is fine (4.3×, identical digests) — that was a free held-out pass left on the table.
- The structural ceiling the author names (carrying cell occupancy across chronons, bodies moving ≤1 cell per chronon) is the actual gold path for this stepper; this run is the first half of that deletion.
