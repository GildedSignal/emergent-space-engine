**What the author missed.**
- No control against measurement confounds: the −15.3% rested on one machine, one build pair, min-of-alternations; a clean-rebuild A/B or a second host would have shown crowded's true gain (~1%) before the dossier's headline. The claim's biggest number sat on the world where the mechanism is weakest (crowded has no container, so `first_wall` never runs there — the gain had to come from `entry_time` alone).
- The mechanism was never confirmed structurally: both binaries contain 5 static `__divti3` references; the author did not check (objdump/perf) that the *hot* call sites actually left the software routine, only that time moved.
- `bench.rs`'s `TOTAL` line divides by zero accumulators (`total_ns`/`total_ops` are never summed) — dead output.
- ns/op weights `random-pass`'s 44M ops most; a per-stage ops-mix report (the author's own second blind spot) would have shown the division fix's audience is container worlds, inverting the headline before it was written.
