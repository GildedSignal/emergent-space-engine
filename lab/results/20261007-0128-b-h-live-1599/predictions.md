# Predictions (written before the decisive runs)

The instrument: H_live = the per-body integer words beyond each body's compiled tube (the fit's remainder and sub-quantum turn, the sigma-delta carries, the clock's energy register, the kick ramp's impulse), a ledger of created/reabsorbed/spill bits at every event, both on `xtask universe --bench` and the page. Not tuned on anything below; all of these are falsifiable by the runs.

1. **Digest identity (the kill criterion for the implementation).** The same seed, input log and cut give the same universe digest with and without the instrument, at every rtf I run (1, 10, 100, 1000). If any digest differs, the instrument writes, and this implementation is wrong (the measure survives; the code does not).
2. **Ledger closure.** In every run, `Δ(created + spill − reabsorbed) = Δ(live stock bits)`, exactly (the bench prints `closes`, the unit test asserts it on a scripted flight with births, handoffs and losses).
3. **The stock does not grow with game time.** Per live body the stock stays inside a fixed envelope (I expect ≤ ~300 bits/body: each word is bounded by a quantum or a word width); the *total* grows only when bodies are born (leavers). Over a 30 s rtf-100 flight (3,000 game seconds, several low orbits) the per-body number at the end is within 2× of its value after the first game second.
4. **Creation is dominated by kicks; reabsorption nearly balances it.** I expect creation of order 10¹–10³ bits per game-second for the whole scene (≈ 28 bodies, ~64 kicks per orbit, low orbits ~5,000 game-seconds: a few bits per body per game-second), decision bits a small tail, and reabsorption of the same order (kick payloads fold back into new tubes), so the net balance is much smaller than creation. If creation ≫ reabsorption and the stock walks, that is a finding about the law, not the instrument.
5. **The rates per game-second are rtf-invariant for kicks, and scale as 1/rtf for decisions.** The script burns every 240 nominal frames = every 4·rtf game-seconds, so decision bits per game-second fall as rtf rises, while kick bits per game-second stay within the same order (same laws and cadence per orbit). 
6. **Gates.** `behave --law plane --gates B12,B13,B14,B17` prints the same detail lines before and after (bit-identical outcomes; B14's timeout line within noise on this shared machine).
7. **The reading for the board (not a gate).** The per-body creation rate, times 10⁹, is the churn a population store must absorb per game-second; I expect it small enough (≤ ~10 bits/s/body at the plane's densities) that reabsorbing stores keep a billion bodies in bounded live memory — the measure's answer to "distinctions, not body count, decide whether 10⁹ fit".
