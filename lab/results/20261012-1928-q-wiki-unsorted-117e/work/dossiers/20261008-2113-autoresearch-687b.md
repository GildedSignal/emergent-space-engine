# Dossier — 20261008-2113-autoresearch-687b

**Claim.** The galaxy readout's per-sample cost (18–27 ns/sample wall at 4 threads; splat = 94% of the frame) is not scalar-arithmetic-bound: an exact reciprocal division replacing the u64 div/mod in `locate`, plus an f32 projection, hold every frozen gate and buy a paired median of **0.93× (range 0.87–1.01, n = 7 cases)** — real but ≤ 13%, so the lever for the readout is not scalar micro-optimization; the cost sits in the pad gathers, the scattered plane read-modify-write and per-frame fixed overheads, and the changes that would beat this local optimum are sample batching per compiled orbit (SoA pad), image tiling, or moving the splat to the GPU.

**Bottleneck.** Board focus "cost at a billion" / the readout's cost. `xtask galaxy --bench` renders 10⁹ ships (1e6 real tubes + ~10k family generators, 13,963 compiled cycles) — the only artifact at billion scale that works. Fermi before the run: u64 div ≈ 30 c of ≈ 240 c/sample ⇒ at most ~12% — below a gold, worth one probe. Measured: paired ~7%; the div was mostly hidden latency.

**Evidence** (from the repo root, release build; each command ≤ 60 s unless noted):
- Breakdown (added to the bench JSON by this run): `./target/release/xtask galaxy --bench --frames 60 --pace 0` → far 31.6 ms = plan 0.35 + splat 29.75 + tone 1.16; 1,706,760 samples; 218 MB peak RSS.
- Not plane-cache-bound: same bench at 480×270 / 960×540 / 1920×1080 → 22.4 / 17.4 / 16.5 ns/sample (flat to improving as plane bytes grow 16×).
- Exactness: `cargo test --release -p xtask galaxy` → **11/11** (9 frozen gates + the new differential `magic_division_matches_hardware`: 2,000 pseudo-random dividends per real period, 0 mismatches). Offline: 610,154 adversarial (d, n) pairs, 0 mismatches; exact when floor_log2(d) ≥ 1 (error < 2⁻ˡ ≤ ½, one correction suffices).
- Paired A/B, pristine vs candidate binaries, interleaved in the same window (load average 5–8, shared box; absolute ns drift ±15% between windows, ratios are the evidence):
  `far 0.888 · seed7 0.991 · mid 0.942 · deep 0.866 · far(40f) 0.932 · threads1 0.933 · deep(40f) 1.014` → median **0.932**, never slower beyond noise. Single-threaded (threads1) confirms the gain is not a scheduling artifact.
- Reproduce the A/B: build both binaries (candidate = this patch, baseline = pristine), then alternate `xtask galaxy --bench --pace 0 --frames 40 [--seed 7 | --threads 1 | --w 1920 --h 1080]` and take median `ns_per_sample` ratios; script shape in `log.md`.

**Predictions** (`predictions.md`, written before the paired run): P1 "within ±10% on every held-out case" — held on 6/7, exceeded in the good direction on one (deep 0.866); the honest summary is "small real gain, not the suspected 12%-from-division alone". P2 gates stay green — held (11/11). P3 cost is memory-traffic-shaped — supported (flat plane-size curve + null-ish scalar result).

**What would make it wrong.** The M1 has cheaper integer division and a different cache shape; there the division's removal may buy nothing and the f32 change could matter more (NEON). If any paired case regresses > 5% on the M1, drop the f32 projection and keep the division (it is exact and free). The gain is 3rd-order: adopting only for exactness/simplicity is legitimate, adopting for speed is not.

**Cost of adopting.** 163-line patch, all inside `xtask/src/galaxy/` (scene.rs: `dmag`/`dsh` fields + 6-line `locate`; draw.rs: f32 `Proj`; mod.rs: plan/splat/tone medians in the bench JSON; tests.rs: differential test). No behaviour change, no dependency, no cost to other paths.

**Fit with PRINCIPLES.** "The cheapest compute is compute not done" (P1): the division is deleted, not tuned. "Measure before claiming … the simplest falsifying test first" (P10): paired A/B with the pristine build as the standing control. "A failed experiment kills that configuration, never the method" (P9): the null-ish result kills scalar micro-opts for the readout and names the structural lever. "Rough first, refine when a certificate could break" (P21): the readout is a derived cache that decides nothing; its exactness gates still hold bit-for-bit on the division path.

**The lens (autoresearch) and what it missed.** The loop stopped after two sub-10% tuned-case rounds — correct by its own stop rule, but it optimized inside a representation it never questioned (P19: "a fix signals the wrong representation"). What would beat this local optimum: (a) batch 4–8 samples per compiled orbit, SoA pad, vectorized Catmull–Rom — amortizes rec loads and turns the two interpolations into wide f32 ops; (b) tile the image so one thread's working slice fits L2 (the diagnostic says plane capacity is not the binding constraint *per sample*, but tile locality also fixes the scattered RMW chain); (c) move the splat to the M1 GPU (`lattice-metal` exists for other paths) — the honest structural answer, since the readout is pure throughput arithmetic into a texture. And the board's own deeper question stands untouched: H_live (distinct pixels per game-second) decides the billion-body budget, not ns/sample.
