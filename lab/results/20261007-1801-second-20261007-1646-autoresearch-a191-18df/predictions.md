# Predictions (written before the decisive experiments)

Two decisive experiments, both on this shared box, so only ratios and digest equality are load-bearing.

## A. Regeneration: the scope-free deletion

The shipped record must regenerate the author's numbers from the patch alone. I rebuild the deletion
(`proper0` + `readout_state` + `rebind_at`) with every prof scope stripped (no `prof.rs`, no
`scope()` calls, no `dump()`), i.e. what adoption would land.

1. **Interleaved A/B, base vs scope-free opt, four dossier scenes** (tuned m48/rtf100, m24, m96,
   rtf60, 20 s each): I expect the made-kick median to drop 16–21 % and the leaver median to drop
   6–11.5 %, reproducing the author's claimed ranges — unlike the author's as-shipped patch, which
   the checker measured as a leaver *regression* (+9–12 %). If the leaver median drops by < 3 % or
   regresses, the regeneration claim fails.
2. **Digests bit-identical** between base and opt in every scene (`replay_digest` and canonical
   `digest`, `refused` 0). Any difference kills the run.
3. **Test suites green** on the patched tree (`cargo test --release -p emergent-universe -p
   emergent-space`).
4. Adversarial edges the checker added (m200, rtf10): gains should hold (made −13…−21 %, leavers
   −5…−12 %).

## B. The cadence experiment (the checker's named gold experiment, cheapest decisive part)

The profile says compile is 60–66 % of each kick and exact keys never repeat, so the only lever on
the kick path is fewer rebinds per orbit. Cadence is `Config::step_log2` (default 7: 2⁷ kicks per
radial period), a config value. I add a `--step-log2` passthrough to the kick bench (an experiment
scaffold, not a law edit) and vary it.

5. **Cost linearity**: at step_log2 6 and 5 (2× and 4× coarser), distinct kicks replayed (samples)
   and cycle rebinds fall ≈ 2× and ≈ 4× per orbit; the per-kick median stays within ±15 % of the
   step_log2-7 value (compile share is per-rebind and orbit shapes barely move); so total resolver
   work per orbit falls by the same factor as cadence (exponent ≈ 1). If per-kick cost rises ≥ 2×
   as cadence halves (bigger steps → costlier splits), the linear lever is broken and I report that.
6. **The behaviour price**: the shipped ladder (`the_readout_error_falls_as_the_step_squared`,
   `jacobi` example) says readout error is second order in the step, so doubling the step should
   grow the worst Jacobi error ≈ 4× while halving the work: I expect the jacobi example at 6 and 5
   to show ≈ 4× and ≈ 16× the step-7 error. That is the tradeoff table q-cadence starts from; where
   it lands is the integrator's one-way door, not mine.
7. **Digest**: the cadence runs change the scene (digest will differ from step-7) — expected, not a
   bit-identity claim; only the deletion (A) claims bit-identity.

Kill criteria: A fails if any digest differs or the gains are not regenerated by the patch alone;
B fails as a *justification* if work per orbit does not fall with cadence (exponent < 0.7 over
7→6→5), because then q-cadence's premise (kicks dominate, per-kick cost flat) is wrong on the
shipped harness.
