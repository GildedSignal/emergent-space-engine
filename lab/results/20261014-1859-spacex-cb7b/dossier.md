# Dossier — the birth-grid stagger, measured (20261014-1859-spacex-cb7b)

## Claim
The first-kick wave's height is a generation accident, not an engine property: spreading the ladder's
birth grid over one clock step (each ship's first kick delayed by a uniform draw over one step,
`ES_STAGGER` in `work/patch.diff` — birth-only, ships only, ~10 lines in `plan_clock`, no engine term
touched) flattens the wave's arrival width **20.2×** (1,491 → 30,109 game-s, ≈ one step, exactly
bf21's estimate) and **deletes its monster frames** on clean main at 10⁵ burn — events/frame max
6,712 → 338 (**19.9×**, the census ratio), wave-region over-budget frames 5 → **0**, worst frame
338.1 → 34.4 ms — with refusals 0, dead 0, and every non-belt counter identical (boundaries 32,368 =
32,368; handoffs 1 = 1; lost 25 = 25; opens 433 = 433; catalogue 100,076 = 100,076).

## Bottleneck
Bodies in the flyable engine, 10⁶ → 10⁹ (the board's furthest gap, 13 October). The current break at
10⁵–2×10⁵ is the first-kick wave (taleb-6138); two runs name the stagger as the unmeasured lever:
bf21 ("a generation choice: stagger the birth grid over one step → ~24× flatter drain utilisation,
unmeasured here") and cf45 (at 10⁹ "birth-phase staggering is not optional": the birth wave is 26×
the steady stream). The engine-side half (the capped pull, bf21; the pull-hold drain, 4487) holds the
*frame* but not the *load shape* — at 10⁶ the frame holds and real time does not (~34 s of lag per
wave pass, bf21's open direction 0). This run measures the generation-side half, alone, on clean main.

## What would make it wrong
The stagger's one-shot cost is a first interval up to ~2 steps long with the kick's weight still Δs:
if the behaviour gates (B13/B14, not run here) reject that error class, the implementation must
stretch Δs with the delay. The flight covers 21 k game-s of a 30 k spread: the flown second wave is
missing (the census plus the clock's per-body next-half planning — bf21's measured continuum, no
shared grid — is the evidence arrivals stay spread). A player inside the belt band during a
staggered wave remains untested (bf21's exposure). The lag number is unchanged (1.448 s both arms,
dominated by frames common to both) — the stagger's lag benefit shows at 10⁶ (bf21's ~34 s/pass),
not at this rung. One box, one seed pair flown, planar belt, e σ0.07.

## Fit with PRINCIPLES
"#14 No work for no reason" — the synchronized birth grid is an accident of building every body at
tick 0, and the wave it manufactures is work-shaped, not physics-shaped. "#4 no categories" — one
uniform rule over clock ships, no regime test. "#12 Smoothness" — the monster frames were the p100
tail; the deletion is structural. The lens (SpaceX): the requirement "all bodies born at tick 0" has
no owner; delete the accident instead of budgeting the spike it makes — the same conclusion the
engine-side fixes (bf21, 4487) reached from the other side, with the second seam now the convergent
residual of both paths.

## The lens
Delete-first framing risks under-selling the complement: the engine-side pull cap and this
generation-side stagger are not rivals — at 10⁶ the cap holds the frame while the stagger is what
keeps the drain current (the load shape). The lens may also have missed that the remaining binding
term (the second seam, 1-9 event frames at 33-36 ms from 5×10⁴ up, burn only) is now the cheapest
next diagnosis on the topic — a2c1's walk-all and cap are the named suspects, and this run adds
nothing to that hunt.
