## What would make it wrong

The pass numbers are one quiet-ish pass each on a shared box (paired flights, seed spread < 7%;
the box's ±10% load noise bounds them; the one artifact cell is marked and excluded from ratios);
the M1 re-measure is the integrator's, as always. The identity claim rests on 35 grid flights
(7 cells × 5 arms, digests pairing) plus five suite runs; the constants cache is exact only where
verified: same tick, `step_log2` as at build, body not a source — all guarded, and a miss falls
through to the live sum. The `state` arm's error path (a shared read that errs) surfaces the error
before `constants` where the shipped path would surface it after the read inside `project` —
unobservable in `replan` (errors become `alive = false` there) and in every flight flown. If a real
birth ever arms the table where a source read errs, the table now disarms instead of serving
shorter answers — that is the fix working, not a change in behavior. `apply` and the one readout
are the pass's floor on this law; anything below 8 µs/body needs the program store, not sharing.

## Fit with PRINCIPLES

"Less is more. The cheapest compute is compute not done" — the shipped pass computed each clock
body's exact state three times and each doll's constants ~N times; none of that was information.
"Compute only surprises… nothing is evolved that can be derived when looked at": the per-doll
`(Δs, c, b)` is looked-at-derived, now derived once per doll. "A fix signals the wrong
representation": d31c's ≲13 treated the pass as reads; this run's `state` arm treats it as
duplicate reads — also wrong (1.4×); the pass was *per-body recomputation of shared quantities*,
and the right representation (what varies per body vs per doll vs per tick) cuts 3× and leaves a
bill that is genuinely per-body. "Store the generator, not the generated": the table stores one
readout per source and one sum per doll, not N copies.
