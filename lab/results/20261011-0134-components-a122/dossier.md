# Dossier — 20261011-0134-components-a122 (components lens)

**Claim.** The storage design (bijection program + sparse scars, `crates/shipmem`) cannot hold a belt at 10⁹ under the plane's own secular tide: common-mode Laplace–Lagrange precession from Giant scars every body within seconds of play at 100×, and the shipped scar layer charges ~130 bits per body for it (16 GB at 10⁹, against the 8 GB budget) — the secular drift must be **derived** (a per-band phase schedule plus the body's own rate from its program state), which takes it to ~0 stored bits and leaves encounters (~163–227 bits per scar, ≤ 0.02 scars/body/orbit) and the player as the only real H_live.

**Bottleneck.** Board risk "Distinctions created per game-second (H_live): they, not the body count, decide whether 10⁹ fit in 8 GB; not measured yet" (HANDOFF 6 October). This run measures it for the storage component: the idiot index is ~10⁵–10⁶ (130 bits/body measured vs ~0.001 bits/body floor), and it deletes the scar layer's secular role — the b-h-live build and b-belt-wire must build the derived drift, not instrument a store that drowns.

**Evidence.** All from `lab/results/20261011-0134-components-a122/work/hlive` (N = 65,536 belt bodies, banded p, Rayleigh σ_e = 0.05, law-native keys via `Key::darwin`; the plane's scene: Sun-mass star, belt 2–3.5 AU, Giant = Jupiter at 5.2 AU, μ = 2⁻¹⁰ — `crates/universe/src/scenario.rs`).

**Predictions.** `predictions.md` was written before the corrected run. Held: P1 (control), P5's encounter half (≤ 0.3 GB at the crate's rates), P6 (table dies at long horizons). Failed, and reported as failed: **P2** — the scar layer does not absorb per-band common-mode drift (130 bits/body, not ≤ 5); **P3** — the differential variant sits at ~138–148 bits/body (saturation, not 3–20 bits); **P4** — bits per scar is 163–227, not 30–80. The pilot (with a sign error that made precession 10⁴× too large) had already shown the same ~127–130 saturation, so the flat cost is structural in the layer, not a magnitude effect.

**What would make it wrong.** If the plane's belt bodies never receive the secular tide (b-belt-wire is unbuilt; if belts stay static programs the result is moot — but then gravity is not a field held by cells, and the fleets already take the planet's tide as integer kicks, `crates/universe/src/fleet.rs`); if the kick layer applies the orbit-averaged tide per band rather than per body — that is precisely the fix this run recommends, so it confirms rather than breaks the claim; if my belt's column widths inflate the scar rows (the 130-bit flat cost across a 10⁵ horizon range and two delta magnitudes argues it is structural). Adoption cost: the belt's evaluate path derives ω(t) from the program state (band schedule + rate from the body's own p, e), bit-exact against the kick layer's accumulators; the scar layer keeps only encounters and the player's light cone, with the scarred fraction capped (at 0.02/orbit a 10⁹ belt accumulates ~8 bits/body per 1,000 h — 1 GB — so re-fit/repack cadence is set by encounter saturation, and that is the allocator's H_live input). Fit with PRINCIPLES: "Compute only surprises. Nothing is evolved that can be derived when looked at (clocks, redshift, views)" — the secular drift of a banded belt is exactly a clock, not a surprise; and "A fix signals the wrong representation" — storing the drift was the wrong representation, not a tuning problem.

**The lens.** One component measured in isolation: the kick layer's per-body sub-quantum accumulators (bounded, a one-time ~16 bits/body, not a rate) are not modelled; the encounter-rate scaling with N at fixed density is taken from q-candidate-degree's finding rather than re-measured; the scar layer's internal cost structure (why a constant within-band delta costs a flat ~130 bits/row — the row codec appears to lack a constant-column form) is unexplained and is the cheapest follow-up: one look at `Scars::from_deltas`' block encoder with a planted constant-delta column. A local optimum may also hide cost in the reader: deriving dϖ/dt per read must stay cheaper than the scar layer it deletes.
