Grade: silver

**Abstract.** Claim: a bitmapped base-2 timing wheel replaces the shipped indexed 4-ary heap calendar at 2.2–4.5× lower cost with the identical (tick, id) stream. Reproduced: digest-exact on reruns (A/2²⁴ seed 2: heap 4465, wheel 892 ns/op, ratio 0.21; tails 4.6–6.7 vs 1.6–2.0); diff mode clean on A–D; floors regenerate. But the headline ratio is storm-specific: on a spread workload (log-uniform delays, 21 octaves) the wheel wins only ~1.6× at 2²², and in a reachable all-beyond-horizon state the wheel delivers a body at a stale entry's wrong tick (corner probe: 3145728 vs 4194304) — the identical-stream claim fails there. Idea is a prior-art lead (original-research-report.md:643), finally measured. Adopt only after the overflow fix and honest per-regime gains.

**Reproduction.** Clean tree, `git apply` unnecessary (patch.diff empty; bench is a standalone workspace). All dossier commands rerun: digests match stored rows exactly (A/2¹⁸ seed 2 and A/2²⁴ seed 2, heap and wheel), ratios within load noise (0.21 vs 0.22 claimed; steady-state storm at 2¹⁸ ≈ 0.44), tail medians match (wheel 1.6–2.0, heap 4.6–6.7 at 2²⁴), floors 1.41/2.73 ns vs stored 1.33/2.01. `diff` mode: no divergence on all four cases. Incumbent verified structurally verbatim against `crates/lattice-event/src/lib.rs:218-317`. Predictions were pre-registered and outcomes reported honestly, including the failures (P2b, P5, P6, P7) — good discipline.

**Adversarial cases (three, beyond reproduction).**
1. **Correctness corner, fails.** All bodies beyond horizon W, one re-timed far-later: `next_tick` returns the *stale* overflow entry's tick (1.5·W instead of 2·W) and `deliver` emits the first *live* entry at that wrong tick — silent divergence, no panic. Cause: the `any()`-false fallback reads `over.first()` without a staleness check, and the due-loop pops until live regardless of tick. Reachable in a quiet region where every pending event lies beyond W (the dossier's own case D argues such events exist); the author's workloads never empty the wheel, so P1's 0-mismatch record has a hole exactly where the lens looked away.
2. **Spread regime (cases E/F: log-uniform delays over 21/30 octaves), magnitude does not transfer.** Digests match, wheel still wins everywhere — but 213 vs 136 ns/op at 2²² (1.6×), not 2.2–4.5×; with ~30% beyond W, 1.3–2.3× and noisier. No regime found where the heap wins; the *direction* of the claim generalizes, the *size* does not.
3. **Large-N rows are one-shot.** Stored rows show `sets` = 1–2 at N ≥ 2²⁰: the churn stream is never consumed; those rows measure initial fill + one mega-storm drain divided by 500k ops. The dossier discloses the storm but not that the run never cycles at those sizes; the steady-state storm ratio (2¹⁸, sets ≈ 499k) is ~0.43.

**Novelty.** `docs/reference/original-research-report.md:643` already proposes benchmarking "radix heaps or hierarchical bucket queues" for integer ticks; no H entry ran it. This run supplies the measurement — a lead executed, not a new idea, and no premise is overturned.

**Goal fit.** Real component (plane.md foundation 2; the crate comment names sift-down as the calendar's cost driver), PRINCIPLES #12/#16/#17 well served by the bitmap-and-CLZ design. But the dossier overstates the crate comment ("the queue is the measured hot spot of the sparse order" — the comment says sift-down dominates *within* the calendar), and the measured gain is 1.6–4.5× by regime, below the 10× gold bar. Tail percentiles sample `set()` latency only; the drain/sort inside `deliver` is unsampled, so "flat p999" describes the set path alone.

**The one experiment to gold.** Fix the overflow staleness corner (pop-until-live in `next_tick`'s fallback; tick-check in the deliver due-loop; re-run diff mode plus an all-far workload), then measure a mixed spread+storm workload in steady state at 2²⁰–2²⁴ and restate the gain per regime. If the wheel holds ≥ 2× at DRAM scale with correctness closed, it is a cheap ~150-line adoption.

**What the author missed.** The stale-overflow corner (above); the spread regime; that the linear control ties the wheel on case A at small N (45 vs 37 ns/op at 2¹⁶ — only case C separates, 12–15×); that the 24 B packet is 24 GB at 10⁹ bodies against the 8 GB target, so the "joins the body's record" path needs `shipmem`'s packing, not an assertion; and `results/caseA-soa.jsonl` is regenerable only in digest, not by any mode in the shipped code (leftover of a removed variant — unused by the dossier, but it should not have been kept).
