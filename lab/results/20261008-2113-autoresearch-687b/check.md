Grade: silver

**Abstract.** Claim: the billion-ship readout (splat ≈ 94% of frame) is not scalar-arithmetic-bound; exact reciprocal division + f32 projection buy ~7%, so the levers are batching/tiling/GPU. Reproduced in a clean tree: gates green; 13,963 cycles and 1,706,760 samples exactly; plane-size curve flat-to-improving (31.0/25.7/24.6 ns at 480/960/1080p); my own interleaved A/B medians far 0.917, mid 0.905, deep 0.913, threads1 0.88–0.94, matching the reported 0.93. Adversarial: the magic division is wrong for power-of-two periods (magic = 2⁶⁴ truncates to 0), so "proved exact for period ≥ 2" is false — latent only (0 of 9,678 real periods across 6 seeds are powers of two). ≤13% moves no board bottleneck; the honest negative result is the content. Adopt cost: 163-line patch plus a power-of-two guard.

**Reasons.**
- *Reproduction (clean tree, `git apply work/patch.diff`).* `cargo test --release -p xtask galaxy` → 10/10 pass (9 frozen gates + `magic_division_matches_hardware`). Note: the dossier says 11/11; the suite is 10 galaxy tests — minor count error. Bench: 13,963 cycles compiled, far samples = 1,706,760 (both exact); far 60-frame breakdown plan/splat/tone = 0.58/37.6/2.9 ms → splat ≈ 91% (author's window: 94%). Absolute ns/sample 24.5 in my window vs 18.5 in the author's — the shared box drifts, exactly why the pairing protocol is right.
- *Diagnostics reproduce.* Plane size 480×270/960×540/1920×1080 → 31.0/25.7/24.6 ns/sample: flat-to-improving as plane bytes grow 16×, confirming "not plane-cache-bound".
- *Paired A/B (my own, interleaved base/cand, 3 reps).* Medians: far 0.917, mid 0.905, deep 0.913; single-thread 0.935/0.884. Consistent with the reported median 0.93, range 0.87–1.01. The gain (~7–9%) is real but bounded as claimed.
- *Adversarial 1 — exactness proof is false at power-of-two periods.* `dmag = (1u128 << (64+dsh)) / period` equals exactly 2⁶⁴ when period = 2^k, and the `as u64` cast truncates it to 0; `locate` then returns q ∈ {0,1}. Offline check (same arithmetic as the patch): d=2, e=4 → q=1, r=2 (want q=2, r=0); u64::MAX cases off by ~2⁶³. So the patch comment and the dossier's "proved exact for all u64 dividends when period ≥ 2" are wrong; the correct condition is "period ≥ 2 and not a power of two" (fix: one line, `if period.is_power_of_two() { n = e >> dsh }`, or the add-form magic). *Latency:* I scanned 9,678 real compiled periods over 6 seeds: zero powers of two, and 483,900 differential divisions clean; if one ever occurred the frozen `drawn_positions_agree_with_cycle_readouts` gate would fail loudly. So the shipped gates were never at risk today — but the "adopt it because it is exact" argument rests on a proof that does not hold, and nothing in the code prevents the case.
- *Adversarial 2 — extreme plane sizes* (16× span, above): behaviour matches the memory-traffic diagnosis; no regression beyond noise.
- *Adversarial 3 — single-thread*: gain persists without the scheduler (0.88–0.94), so it is not a threading artifact.
- *Predictions.* predictions.md pre-registers P1–P3 with the held-out case list and discloses the post-run outcome as appended. File-time verification is impossible here (the whole run folder was published at once), but the log's ordering and the disclosed appendix are consistent with pre-registration; P1 held 6/7 with the honest good-direction exception reported.
- *Novelty.* git log on `xtask/src/galaxy/` shows three commits, all construction (renderer, jobs, tone) — no prior micro-optimization; HISTORY has no readout-cost entry. The magic-division technique itself is standard prior art (Granlund–Montgomery, which the author cites); the run's claim to interest is the measured negative result, which is new for this artifact.
- *Goal fit.* Honest, measured, controls on both sides (pristine-build pairing, gates as the standing control) — good PRINCIPLES hygiene (P10 "measure before claiming"). But the readout is the view instrument, not the engine: the board's live list (kicks, changeover, encounters, tide, shipmem, candidate scaling) does not include it, and a ≤13% effect moves no bottleneck by 10×, deletes no component, and kills a premise (scalar-bound readout) that the run itself posed. "The view is an instrument" (P28) caps how much this can matter.

**The one experiment that would make it gold.** Build the structural lever the negative result points at on the same artifact — batch 4–8 samples per compiled orbit with a SoA pad (or tile the plane to L2) — and show the readout's ns/sample drops ≥ 10× with the same gates green. That converts "not scalar-bound" from a suspicion into a deleted cost, and it is one step on code the run already instrumented (plan/splat/tone split). Alternatively, a smaller-scope gold is not available from this direction.

**What the author missed.**
1. The power-of-two-period hole: a false "proved exact" claim, no guard, and a differential test that only covers periods that happened to occur. One line fixes it; until then even the "adopt for exactness/simplicity" path is unsound as stated.
2. The gate count (11 vs the real 10) — small, but a checker finds it.
3. The cheapest representation change for the division was not tried: keep the orbit count per tube/materialized ship incrementally (carry `(n, s)` forward per frame) so `locate` never divides at all — deleting the op outright (P19: a fix signals the wrong representation) instead of making the division faster.
4. No probe of the M1/NEON shape (acknowledged in "what would make it wrong", but the f32 change is exactly where x86 and M1 diverge most).
5. RSS claim (218 MB) not re-verified against the same 60-frame command; my 5-frame spot run peaked at 107 MB — no risk either way on an 8 GB target, but the number is unconfirmed.
