**What the author missed.**

- The same waste survives in `view.rs:264`: `orbit_state(event_time).proper_time` recomputed per readout. One line to convert, and it is in the *frame* path (the gather is 83% of a light frame, H0210) — likely a bigger win in `frame_ms` than this patch is in `kick_us`.
- `proper_since` (step.rs 274) recomputes the event readout whenever `since == event_time` — the common retired-segment case, same fix.
- Memory cost is understated: the bench measures `bytes_per_body` 1203→1221 (+18), not "a Scalar, 10 bytes with padding".
- `replay_digest` necessarily changes across this patch (it hashes `{:?}` of the record, which gained a field). Canonical outcomes are pinned by the scene digest, but any tooling keyed on `replay_digest` will false-alarm; the dossier should have said so.
- One genuine semantics edge the dossier does not name: old `orbit_state` could refuse when the discarded integer word overflowed (`cartesian`); `decode_orbit` cannot. Only Err→Ok, never observed (refused 0 in all configs), but "bit-identical" is proven on the tested scenes, not in all possible cases.
- Test count recorded as 74 vs the current suite's 104 — a regenerability-of-record slip of the kind H0212 warned about, though the numbers that matter all regenerate.
