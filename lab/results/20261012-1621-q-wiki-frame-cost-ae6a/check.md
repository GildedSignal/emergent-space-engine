## The one defect (fix at adoption, one line)

`regen.sh` applies its patch with `git -C "$ROOT" apply work/patch.diff` — a repo-root-relative path that never resolves from the run folder. From a clean checkout the apply step fails (the archived regen.log line 1 shows exactly this), the probe silently benches four **identical 400-member scenes**, and regen.sh still exits 0. I verified the silent clamp on a clean build: `--members 400` and `--members 1024` both digest `11ad8fb9…`. The archived numbers are genuine (the tree was still patched when the runner ran it, and I reproduced the digests with the patch applied per the dossier's stated precondition), but a future clean-tree regen would wrong-pass. Fix: `git -C "$ROOT" apply "$ROOT/$R"…` or run the apply from the run folder with `git -C "$ROOT" apply --check "$(pwd)/work/patch.diff"`.
