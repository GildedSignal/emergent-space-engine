# Assessment after the evolving spacetime patch

The project has made useful progress toward a shared geometric laboratory, but it is drifting when local fixture completion is treated as evidence that the spacetime compiler is approaching its scaling goal. The next milestone should demonstrate that completed physical work is actually reused. This assessment follows the user's request to make gravity intrinsic to the compiler and their concern about drifting from success.

The latest inspected journal reaches H0045. The newer patch supersedes the earlier GEM-only draft as the useful current experiment: it shares a geometry object across source/test-body evolution, clock readings and a light-delay calculation, and it can be explored in the observatory. Those are advances. The light calculation remains a linearized delay along a Euclidean path. Neither that experiment nor its user interface establishes G2 or amortized physical evolution. No code or gate is changed by this review.

**The current compiler gap is visible in the code.** In [evolving_patch.rs](../crates/law-lab/src/evolving_patch.rs), CompiledGeometry::compile stores source histories and computes their digest (reviewed lines 499–512); phi_xi still searches those histories and evaluates source contributions at every query (514–570). Both advance_patch and advance_from_cache loop over every admitted tick (1287–1334). Each step clones the patch and growing histories and recompiles the geometry container (845–854, 1150–1256). With untruncated histories growing linearly in tick count, repeated full copying gives quadratic cumulative copy work; this is code-derived complexity, not a measured runtime claim.

The cache fixture checks answer equality (1507–1525). It does not measure eliminated source evaluations, eliminated steps, construction cost or break-even reuse. A slow ticked reference is useful and should be retained. The missing item is a separate accelerated evaluation of the same law that avoids identified work. A method called compile or cache is not that evidence by itself.

**One common response contract connects the existing ideas.** For a finite spacetime block B, define R_B to map admitted incoming data to outgoing data. Incoming data includes the initial cut, incoming matter/worldtubes, field and exterior history, interventions, law identity and boundary conditions. Outgoing data includes propagated matter, null arrivals, proper time, field/source contributions, events, exchange accounting and any state needed for later influence. The response also carries its domain, dependencies, whole-interval certificate and reconstruction recipe.

This is a contract to implement against a selected law, not a new physics law or a request for a general framework first. Its implementation starts in the current patch. Geometry construction is shared among consumers. Responses compose only when their complete boundary contracts match. Identities remain separate even when one operator accepts an indexed family.

There are three distinct reuse claims, to be measured separately:

| Reuse | What is reused | What a passing comparison must show |
|---|---|---|
| Repeated evaluation | Identical admitted inputs and dependency versions | Answers returned without repeating the corresponding physical solve; cache overhead included. |
| Shared geometry | One field/metric representation for distinct consumers | Fewer total source evaluations across a ship/ray/clock cohort, including construction and certificate costs; distinct trajectories retained. |
| Time composition | A response valid across a longer interval | Fewer physical substeps than the reference while preserving full boundary state and all relevant interior events. |

Changed inputs require a fourth operation: propagate a causal delta through the dependencies. Reuse may continue outside the affected future domain, or inside it when a certificate proves the response remains valid for the new input. Validity must cover hidden residuals and future consequences, not merely unchanged current event labels. A small influence cannot be discarded because it is currently invisible. Memoization combined with change propagation has an established programming-language foundation in [Acar, Blume and Donham](https://arxiv.org/abs/1106.0478); applying it efficiently to these physical responses remains to be demonstrated.

The user's influence-of-influenced relation should be represented across time: A at one event affects a later B, which may affect a still later A. Strictly delayed dependencies can be ordered forward in spacetime. That does not prove they damp, become cheap, or disappear; finite-lookahead, same-boundary constraints and simultaneous interactions must be solved according to the law. Causal ordering removes an apparent instantaneous cycle, not the work of arbitrary feedback.

For a genuinely linear admitted subproblem, internal unknowns can sometimes be eliminated into a boundary operator using a Schur complement. This is a concrete mathematical interpretation of caching a region's response. The eliminated block must be invertible, the resulting operator can become dense, and nonlinear matter/geometry coupling cannot simply be substituted into that formula. [PETSc documents those distinctions](https://petsc.org/release/manualpages/KSP/MatGetSchurComplement/). Min-plus remains useful for admitted arrival/route composition; it is not the algebra of the entire gravitational law. Neither technique is selected for implementation merely because it matches the vocabulary.

**The next experiment should use the existing patch as the reference.** Before another law variant or feature, choose one supported nonuniform weak-field workload, establish its same-law complete-state comparison, and instrument source evaluations, physical steps, history bytes copied, response construction, application, invalidation and peak resident memory. Keep the current source-change fixture as a starting point, but include in-flight light on both sides of a subdivision and a controlled input change that reaches only part of the response domain. Add an independently checked metric/clock/null relation; shared object identity alone is insufficient physical validation.

Then implement one reusable response on that workload. Sweep distinct consumers and horizon separately. Require identical same-law outcomes first, then show a positive amortization point with setup, verification and invalidation fully charged. Repeated identical-query memoization is a control, not a substitute for reuse across distinct consumers. Source-summary savings are spatial reuse; they do not establish time compression. Advancing the same tick loop behind a cached geometry object fails the time-composition objective.

Choose the precise bounded workload, numerical tolerances and performance margin before candidate measurement. Preserve existing frozen gates. If no compact same-law response can be derived for the selected law, record that result and reconsider the law/representation choice before extending the engine. Do not attempt to patch that result with an analytic orbit that silently changes the canonical map.

**Proposed priority:** preserve the current patch and observatory as useful research instruments; focus the next physics/compiler milestone on one independently checked, reusable geometric response with measured break-even cost. Pause additional law variants, compact-object extensions and generic abstraction work unless they resolve a demonstrated blocker in that experiment. This is a recommendation, not a command to stop another running task or an implemented optimization.
